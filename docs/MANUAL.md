# Persona Chat — Unity + Java 독립 채팅

> 공개판은 새 캐릭터 3종과 단색 배경을 사용합니다. 기존 비공개 이미지·영상은 포함하지 않습니다. 새 이미지의 자유로운 재사용 조건은 ASSETS.md에 있습니다.

처음 실행한다면 **`00_처음_사용하기.txt`**를 먼저 읽어 주세요. `.env` 설정부터 채팅 시작까지의 간단한 안내입니다. 공유 묶음은 사용 가이드, Windows 실행용 ZIP, 개발용 소스 ZIP을 구분해 제공합니다.

LostMemory에서 사용하던 **유나 페르소나, 3단계 비교, 최근 대화 이력과 초기화 흐름**을 별도 앱으로 옮긴 Windows용 프로젝트입니다. 게임 로그인·던전·DB·Redis·원래 서버 없이 실행하도록 구성했습니다.

Unity의 게임 전용 프리팹과 인증 코드를 복사하는 대신, 동일한 대화 흐름을 독립 UI와 작은 Java 서버로 다시 구성했습니다. 기존 LostMemory 파일을 수정하거나 실행 중 참조하지 않습니다.

**현재 제공 상태:** Windows 실행 파일, Java 서버 JAR, 휴대용 Java 런타임과 외부 캐릭터 설정을 준비했습니다. Unity 6000.3.26f1에서 실제 GPT 대화·3단계·대화 이력·새 표정 전환을 확인했습니다. Windows의 `Start.cmd` 실행과 서버 연결, 창 종료 시 서버 자동 종료를 검증했습니다. 배포는 `dist`의 전용 ZIP을 사용하세요. 개인 키가 있는 개발 폴더 전체를 공유하지 마세요.

## 1. 완성된 배포 ZIP을 받은 사용자

Unity 빌드 후 `scripts/Package.ps1`로 만든 ZIP 기준입니다. Windows 10/11 64비트, 인터넷, 본인의 OpenAI API 키가 필요합니다. Unity·Java·DB 설치는 필요 없습니다.

1. ZIP을 풀어 쓰기 가능한 폴더에 둡니다. ZIP 안에서 직접 실행하지 마세요.
2. `.env`를 메모장으로 열고 다음 두 값을 입력합니다. 원본 소스를 받은 경우 `.env.example`을 `.env`로 복사합니다.

   ```dotenv
   LLM_API_KEY=본인의_API_키
   LLM_MODEL=gpt-4.1-mini
   ```

3. 폴더 맨 위의 **`채팅 시작.cmd`**를 더블클릭합니다. Java 서버가 준비되면 Unity 채팅 창이 자동으로 열립니다. 기존 `Start.cmd`도 같은 기능입니다.
4. 메시지를 입력한 뒤 **Enter** 또는 **전송** 버튼으로 보냅니다. **Shift+Enter**는 줄바꿈입니다.
5. 채팅 창을 닫으면 해당 실행에서 시작한 서버도 종료됩니다. 남아 있으면 `Stop.cmd`로 종료합니다.

키가 비어 있거나 예제 값이면 서버·앱을 시작하지 않고 한국어 설정 안내를 표시합니다. `.env`가 없으면 예제 파일에서 자동으로 만듭니다. 안내 창은 아무 키를 누르면 닫힙니다. 모델 접근 권한이나 실제 키의 유효성은 대화 요청 시 확인되므로, 형식 검사를 통과했다고 사용 가능한 키가 보장되는 것은 아닙니다.

시작 중 또는 실행 중에 다시 누르면 추가 서버·앱을 열지 않습니다. 같은 폴더의 에디터용 서버만 켜져 있으면 `Stop.cmd`로 종료한 뒤 다시 실행하라는 안내가 나옵니다. 다른 폴더의 앱이 같은 포트를 사용 중이면 기존 앱을 종료하거나 `.env`의 `CHAT_PORT`를 바꾸세요. `release/client/PersonaChat.exe`를 직접 실행하지 말고 `채팅 시작.cmd`를 사용하세요.

API 호출 비용은 입력한 키의 계정에 발생합니다. ChatGPT 웹 구독과 API 사용 한도는 별개입니다. 키는 본인 PC의 `.env`에만 입력하고, 저장소나 화면 녹화·채팅으로 공유하지 마세요.

`.env`는 한 줄에 `이름=값`을 적습니다. 값에 따옴표를 붙일 수 있으며, `$` 등을 코드로 실행하지 않습니다. 주석은 별도 줄에 `#`로 시작하세요. 실행 중 설정을 바꾸었다면 앱과 서버를 종료한 뒤 다시 켭니다.

## 2. 제작자: Unity를 한 번 빌드하기

1. Unity Hub에서 **Unity 6000.3.26f1**을 설치하고, 에디터를 한 번 실행해 라이선스를 활성화합니다. Windows Mono 빌드용 구성은 에디터에 포함됩니다. 프로젝트 버전은 `client/ProjectSettings/ProjectVersion.txt`에 있습니다. 한국어 언어팩(메뉴 번역)과 Visual Studio 설치가 끝나기 전에도 에디터 자체 컴파일·Play 테스트가 가능합니다.
2. Hub에서 이 프로젝트의 **`client` 폴더**를 추가해 엽니다. 기존 LostMemory 프로젝트를 여는 것이 아닙니다.
3. 첫 임포트 시 `Assets/PersonaChat/Scenes/Chat.unity`와 `Assets/PersonaChat/Prefabs/ChatUI.prefab`이 에디터 API로 생성됩니다. **Play 전에도 Game 뷰에서 화면과 캐릭터를 볼 수 있고**, Hierarchy의 `Persona Chat > Chat Canvas` 아래에서 텍스트·버튼·레이아웃을 편집할 수 있습니다. 생성되지 않거나 이전 빈 씬이 남아 있으면 `Persona Chat > Create Chat Scene`을 누릅니다. 이 메뉴는 확인 후 기본 UI를 다시 만들므로 사용자 배치 수정은 먼저 다른 씬에 보관하세요. Windows 빌드는 기존 씬을 사용하며 매번 초기화하지 않습니다.
4. 먼저 `.env`에 키와 모델을 넣고 `Start-Server.cmd`를 실행한 뒤 에디터의 Play 버튼으로 대화를 확인합니다. 메뉴 없이 채팅 화면이 뜹니다.
5. 한글 입력·버튼·레이아웃·실제 답변을 확인한 뒤 Play를 끄고 `Stop.cmd`를 실행합니다.
6. 에디터 메뉴 `Persona Chat > Build Windows`로 빌드하거나, 에디터를 닫고 PowerShell에서 실행합니다.

   ```powershell
   .\scripts\Build.ps1 -UnityEditor 'C:\Program Files\Unity\Hub\Editor\6000.3.26f1\Editor\Unity.exe'
   ```

   빌드 결과: `release/client/PersonaChat.exe`와 같은 폴더의 데이터·DLL 전체.

7. `Start.cmd`로 최종 실행을 확인합니다. 실행 파일 하나만 따로 옮기면 안 됩니다.
8. `scripts/Package.ps1`을 실행하면 `dist/PersonaChat-Windows-…zip`을 만듭니다. 사용자 키·토큰·로그는 제외하고 빈 키 예제만 넣습니다. **키가 입력된 개발 폴더를 수동으로 통째로 ZIP으로 묶지 마세요.**

PowerShell에서 스크립트 실행이 제한되면 해당 명령에 한해 아래처럼 실행할 수 있습니다. 시스템 전체 정책 변경은 필요 없습니다.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Build.ps1 -UnityEditor 'C:\…\Unity.exe'
```

서버만 다시 빌드: `scripts/Build.ps1 -ServerOnly`. 빌드용 JDK 17이 없으면 프로젝트 내부에 다운로드하며 SHA-256을 확인합니다. 최초 소스 빌드는 Gradle 의존성 다운로드로 시간이 걸릴 수 있습니다.

## 3. 대화·페르소나 설정

### 공개판 UI

단색 남색 배경, 크림색 대화창, 금색 포인트를 사용합니다. 초록색 망토를 입은 새 캐릭터의 평상시·기쁨·걱정/슬픔을 외부 PNG로 전환합니다.

- 사용자 메시지는 오른쪽 노란 말풍선, 캐릭터 답변은 왼쪽 흰 말풍선으로 표시합니다. 긴 답변은 자동 줄바꿈되며 대화 영역을 스크롤할 수 있습니다.
- 선택한 단계만 금색으로 표시합니다. `새 대화`는 이전 `대화 초기화`와 같은 동작입니다.
- 이름표의 표정 표시는 답변의 emotion 값에 따라 바뀝니다. 단계 변경·새 대화·재연결 시 평상시로 돌아옵니다.
- UI는 `Chat.unity`와 `ChatUI.prefab`의 실제 Canvas·Text·Button·RoundedPanel 요소입니다. 말풍선은 실행 중 생성됩니다. 배경은 단색이며 사용 권한이 있는 별도 이미지로 교체할 수 있습니다.
- 기본 창 크기는 1440×900입니다. 한글 입력을 유지하며 Enter는 전송, Shift+Enter는 줄바꿈입니다. IME 조합 중이거나 조합이 방금 끝난 프레임의 Enter는 전송하지 않습니다.
- 입력창은 기본 여러 줄 높이에서 시작하고 내용에 따라 늘어납니다. 최대 높이를 넘는 긴 입력은 커서를 따라 스크롤되며, 위쪽 내용이 보이지 않아도 삭제된 것은 아닙니다. 방향키로 이전 줄로 이동할 수 있습니다.
- 화면에는 최근 최대 80개 메시지 말풍선을 표시합니다. 모델에 보내는 최근 20개 메시지 제한은 기존과 같습니다.

| 화면/파일 | 동작 |
|---|---|
| 기본 3단계 | 관계·말투·행동 범위·예시를 적용한 유나 |
| 1단계 | `prompts/stage1.txt` — 이름만 지정 |
| 2단계 | `prompts/stage2.txt` — 관계와 말투 추가 |
| 3단계 | `prompts/stage3.txt` — 행동 범위와 대화 예시 추가 |
| 단계 버튼 | 설정 변경과 동시에 대화 이력 초기화 |
| 대화 초기화 | 현재 단계는 유지하고 새 대화 시작 |
| 재연결 | 대화 초기화 후 현재 서버에 다시 연결 |

프롬프트 파일은 UTF-8로 수정하고 서버를 재시작합니다. `{{character_name}}`은 `character/character.json`의 `displayName`으로 서버 시작 시 치환합니다. 이름을 직접 적으면 그 이름은 자동으로 바뀌지 않으므로, 이름 변경을 쉽게 하려면 이 자리표시자를 유지하세요. 성격·관계·말투·행동 범위는 계속 TXT에 작성합니다.

### 캐릭터 이름·이미지 바꾸기 (재빌드 불필요)

`character/character.json`을 UTF-8로 수정합니다. 기본 예시는 다음과 같습니다.

```json
{
  "displayName": "유나",
  "playerName": "나",
  "neutral": { "path": "portraits/example-neutral.png", "columns": 1, "index": 0 },
  "happy":   { "path": "portraits/example-happy.png", "columns": 1, "index": 0 },
  "sad":     { "path": "portraits/example-sad.png", "columns": 1, "index": 0 }
}
```

- 이름은 1~40자로 지정합니다. `playerName`은 채팅창에서 사용자를 표시하는 이름입니다.
- 평상시는 손을 내린 자세, 기쁨은 두 손을 모은 자세, 걱정·슬픔은 한 손으로 반대쪽 팔을 감싼 자세입니다. 얼굴·머리·의상은 같은 디자인입니다.
- `columns: 3`은 가로 3등분, `index`는 왼쪽부터 0·1·2입니다. 공개판 3종은 아틀라스가 아닌 개별 PNG입니다. 개별 PNG는 `columns: 1, index: 0`입니다.
- 개별 PNG/JPG를 쓰려면 예를 들어 `{"path":"portraits/happy.png","columns":1,"index":0}`으로 바꿉니다. 경로는 `character` 폴더 기준이며 이미지 파일도 이 폴더 안에 넣습니다. 파일은 16MB 이하를 사용하세요.
- 이미지 비율은 유지합니다. 특정 표정 파일을 읽을 수 없으면 평상시 이미지로, 평상시도 없으면 ‘이미지 없음’으로 표시하며 채팅은 계속할 수 있습니다.
- 이름·프롬프트를 바꾼 뒤에는 앱과 서버를 재시작합니다. 에디터의 미리보기는 **`Persona Chat > Refresh Character Preview`**로 갱신합니다. 이 메뉴는 표정 이미지와 이름을 갱신하며 UI 배치를 다시 만들지 않습니다.

### 답변에 맞는 표정

한 번의 API 요청에서 `reply`(대사)와 `emotion`(캐릭터 표정)을 함께 받습니다. `neutral`은 평상시, `happy`는 기쁨, `sad`는 걱정·슬픔입니다. 사용자의 감정을 그대로 얼굴에 붙이는 방식이 아니라 **캐릭터가 답하며 드러내는 상태**를 모델이 선택합니다. 정확한 감정 진단 기능은 아닙니다.

표정은 답변을 다 받은 시점에 바뀌고, 단계 전환·대화 초기화·재연결 시 평상시로 돌아갑니다. 알 수 없거나 빠진 표정 값은 평상시로 처리합니다. 답변 JSON 자체가 깨졌거나 출력 한도에서 잘리면 기술용 JSON을 대화창에 보여주지 않고 오류를 안내합니다. 실패한 답변은 대화 이력에 넣지 않습니다. 프롬프트 TXT에는 JSON 형식을 직접 작성할 필요가 없습니다.

**대화 이력:** 성공한 최근 10쌍(사용자 10개 + 답변 10개)을 유지하고, 다음 질문을 더해 서버에 보냅니다. 서버가 선택한 캐릭터 설정을 맨 앞에 붙여 API를 호출합니다. 과거 대화를 삭제할 때는 질문·답변 한 쌍씩 제거합니다. 실패한 질문은 API 이력에 넣지 않고 입력창에 복원합니다. 초기화 전 요청의 늦은 응답은 새 대화에 추가하지 않습니다.

대화는 앱 메모리에만 존재하며 종료·초기화하면 사라집니다. 장기 기억·영구 개인화는 구현하지 않았습니다. 초기화/창 종료가 이미 API에 전달된 요청의 처리나 과금을 취소한다는 의미는 아닙니다.

이번 분리판은 **답변이 완성되면 한 번에 표시**하며 3종 정적 표정 이미지를 전환합니다. SSE 스트리밍, 음성, 감정 애니메이션, 게임 동행은 포함하지 않습니다. 원본 게임 UI·인증·DB에 의존하지 않습니다.

## 4. 모델 변경

`LLM_MODEL`을 바꾸고 서버를 재시작하면 적용됩니다. 서버·Unity 재빌드는 필요 없습니다. 현재 연결 대상은 **OpenAI Chat Completions API**입니다. Claude 등 다른 제공자의 키를 넣는 것만으로 전환되지는 않습니다. 모델은 해당 API와 **Structured Outputs (`json_schema`, strict)**를 지원하고 본인 계정에서 사용할 수 있어야 합니다. 기본 `gpt-4.1-mini`를 유지했습니다. 지원하지 않는 모델은 오류를 표시하며 다른 모델로 자동 전환하거나 재호출하지 않습니다.

| `.env` 항목 | 기본값 / 설명 |
|---|---|
| `LLM_API_KEY` | 본인의 OpenAI API 키 |
| `LLM_MODEL` | 기존 시연 설정을 유지한 `gpt-4.1-mini` |
| `CHAT_PORT` | `18081` — 원본 시연 서버의 18080과 분리 |
| `LLM_MAX_COMPLETION_TOKENS` | `1024` — 모델의 출력 토큰 상한. 추론 모델은 내부 추론 토큰도 고려 |
| `CHAT_CONTEXT_CHAR_LIMIT` | `20000` — 앱 자체 문자 수 가드, 모델의 토큰 한도와 다름 |
| `LLM_TEMPERATURE` | 비어 있으면 전송 안 함. 지원 모델에만 0~2 지정 |
| `LLM_REASONING_EFFORT` | 비어 있으면 전송 안 함. 지원 모델의 값만 지정 |
| `LLM_INSTRUCTION_ROLE` | `system`. 모델에 맞춰 `developer`로 바꿀 수 있음 |

모델마다 입력·출력 한도와 지원 옵션이 다릅니다. 긴 컨텍스트나 긴 프롬프트가 좋은 캐릭터 반응을 보장하지 않습니다. 같은 질문·같은 설정·새 대화로 직접 비교하세요. 자동 재시도는 하지 않습니다.

요청 형식은 [OpenAI 공식 Chat Completions 문서](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)를 참고했습니다. 서버는 API 키를 Authorization 헤더로만 전달하고, 모델·출력 한도와 메시지를 구성합니다.

대사·표정 출력 형식은 [Structured Outputs 공식 문서](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=chat)를 참고했습니다. 표정 값이 빠지거나 알려지지 않은 값이면 평상시로 처리하고, 거절·출력 잘림·잘못된 JSON은 별도로 처리합니다.

## 5. 구조와 원본으로부터의 분리

```text
PersonaChat/
  .env.example / .env           키·모델 설정
  Start.cmd / Start-Server.cmd / Stop.cmd
  scripts/                     실행·빌드·포장·점검
  prompts/                     3단계 캐릭터 설정
  character/character.json     화면 이름·표정 파일 경로·이미지 영역
  character/portraits/         외부 표정 이미지 (배포 ZIP에 포함)
  client/                      독립 Unity 프로젝트
  server/                      독립 Spring Boot / Java 17 프로젝트
  runtime/java17/               배포용 Java 런타임
  release/client/               Unity Windows 실행 파일과 필수 데이터
  .run/                        실행 토큰·프로세스 정보·서버 로그 (공유 제외)
  dist/                        키를 제외한 배포 ZIP
```

```text
Unity: 질문 + 최근 대화 + 단계 번호
  → 127.0.0.1 Java 서버: 단계 프롬프트 + .env의 모델·키
  → OpenAI API
  → Java 서버 → Unity 채팅 화면
```

Java 서버는 Spring Web만 사용합니다. DB/JPA/Redis/게임 로그인/JWT/메일/기존 운영 서버 주소에 의존하지 않습니다. API 키는 Java 프로세스만 읽습니다. Unity에 전달되는 `.run/client.json`에는 로컬 주소·매 실행 시 새로 만드는 로컬 인증 토큰·외부 설정의 루트 경로가 들어갑니다. API 키는 포함하지 않습니다.

서버는 `127.0.0.1`에만 바인딩하고 웹 브라우저 Origin 요청을 거절합니다. 개인 PC에서 직접 쓰는 앱을 위한 구성입니다. 공용 서버로 공개하는 로그인·다중 사용자 서비스용 설계는 별도입니다.

## 6. 오류 해결

| 증상 | 확인할 것 |
|---|---|
| Unity client is not built yet | 위 2번의 에디터 설치·최초 빌드 필요 |
| 키를 설정하라는 오류 | `.env.txt`가 아니라 `.env`인지, 예제 문자열을 바꿨는지 확인 |
| 포트 사용 중/서버 이미 실행 중 | `Stop.cmd` 후 재실행. 다른 프로그램의 포트라면 `CHAT_PORT` 변경 |
| 연결 안 됨 | `Start-Server.cmd` 실행 후 Play. 서버 재시작 후 Unity ‘재연결’ |
| API 키/접근 권한 오류 | 키의 유효성, 프로젝트 권한, 계정의 모델 접근 권한 확인 |
| API 한도 오류 | API 잔액·사용 한도·호출 제한 확인 |
| 모델 파라미터/컨텍스트 오류 | 모델 이름·지원 옵션·메시지 길이 확인. 온도·추론 옵션을 비우고 비교 |
| 빈 답변/출력 잘림 | 출력 토큰 한도를 확인. 추론 모델은 출력 예산이 더 필요할 수 있음 |
| 앱 문자 제한 초과 | 새 대화로 비교. 모델 토큰 한도와 앱 문자 제한을 구분 |
| 초기화 직후 요청 처리 중 | 이전 요청이 서버에서 끝난 후 재전송 (최대 약 100초 타임아웃) |
| 서버 시작 실패 | `.run/server.log` 확인. `scripts/Diagnose.ps1`은 키를 출력하지 않고 현재 상태 점검 |
| 한글/화면 문제 | Windows 맑은 고딕과 Unity Play 확인. UI는 OS 글꼴을 사용하며 별도 폰트 파일은 배포하지 않음 |

## 7. 검증과 배포 전 남은 확인

- `server/gradlew.bat test`: 요청 구성, 한국어 HTTP 왕복, 입력 제한, 인증·Origin 거절, 오류 응답 테스트. 가짜 키와 로컬 모의 API만 사용합니다.

- `scripts/Test-Server.ps1`: 가짜 키로 실제 로컬 서버의 실행·인증·종료 검사. 외부 API를 호출하지 않습니다. 기존 서버를 먼저 종료하고 실행합니다.
- `scripts/Build.ps1 -ServerOnly`: 서버 테스트 + JAR 빌드.
- **확인 완료:** Unity 6000.3.26f1 임포트·컴파일, 에디터 미리보기, Play에서 한국어 문장 입력·전송·답변 표시, 3종 표정 전환과 초기화 시 평상시 복귀. 로컬 모의 서버를 사용했고 API는 호출하지 않았습니다.
